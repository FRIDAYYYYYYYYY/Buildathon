# Security Policy & Architecture Guardrails — AegisAI

## 1. Security Philosophy
AegisAI is designed with **Defense-in-Depth** and **Zero-Trust Autonomous Execution Guardrails**. It prioritizes verifiable software security, explicit boundary constraints, and comprehensive auditability.

---

## 2. Core Security Controls

### A. Simulated Mitigation Guarantee (No Dynamic Execution)
- **Zero OS Command Dispatch**: AegisAI will **NEVER** execute generated containment strings (e.g., `netsh`, `pkill`, `taskkill`) against the host system.
- All mitigation outputs generated by LLM triage are passed strictly to [`src/remediate.py`](file:///src/remediate.py), which records the containment command with an explicit `SIMULATED` audit badge.
- No `eval()`, `exec()`, `os.system()`, or `subprocess.Popen()` is ever invoked on mitigation strings or untrusted inputs.

### B. Input Validation & Data Contracts
- Every telemetry event ingested by AegisAI is validated against the strict Pydantic model [`Event`](file:///src/models.py):
  - Numeric boundary constraints (`files_touched_per_min >= 0`, `0.0 <= cpu_percent <= 100.0`).
  - String sanitization and non-empty checks on `user` and `process_chain`.
  - UTC timezone-aware datetime validation.
- Malformed, truncated, or malicious telemetry inputs are rejected at the edge before reaching the rules engine or ML pipeline.

### C. Output Validation & LLM Guardrails
- LLM triage interactions via Gemini are constrained by strict JSON schema definitions matching [`TriageResult`](file:///src/models.py).
- Outputs are validated against literal severity tiers (`low`, `medium`, `high`, `critical`).
- Output parsing incorporates retry-on-failure logic.
- Telemetry injected into prompts is formatted and sanitized to mitigate prompt injection risks.

### D. Secrets Management
- **Zero Hardcoded Secrets**: All credentials and API keys are loaded strictly from `.env` via `python-dotenv` inside [`src/config.py`](file:///src/config.py).
- `.gitignore` explicitly prevents `.env`, `.env.local`, and credential files from entering version control.
- An environment template [` .env.example`](file:/// .env.example) provides configuration guidance without leaking keys.

## 3. MITRE ATT&CK Coverage

AegisAI hybrid detection rules and anomaly models map to the following MITRE ATT&CK techniques:

| Technique ID | Technique Name | Detection Layer |
| :--- | :--- | :--- |
| **T1486** | Data Encrypted for Impact (Ransomware) | Heuristic Rules (Rapid files/min) + Anomaly ML |
| **T1490** | Inhibit System Recovery (vssadmin delete shadows) | Process Regex Rules |
| **T1059.001** | PowerShell Execution Policy Bypass & Obfuscation | Process Regex Rules |
| **T1003.001** | OS Credential Dumping: LSASS Memory (Mimikatz) | Process Regex Rules |
| **T1071** | Living-Off-The-Land Payloads (Certutil / Rundll32) | Process Regex Rules + Novel Process ML |
| **T1078** | Valid Accounts / Impossible Travel | Geolocation Rules + Feature Outlier ML |
